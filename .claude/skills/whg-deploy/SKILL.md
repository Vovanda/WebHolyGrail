# Skill: whg-deploy

> Деплой руками - это запуск штатного `deploy/prod/deploy.sh` с полным окружением.
> Всё остальное роняет живой сайт.

## Когда триггерить

- Выкладываешь коммит на прод сам, без CI
- Деплой упал и надо перезапустить
- Сайт отдаёт 502 после выкладки

## Железное правило: никогда в обход скрипта

Blue-green держит сайт живым: скрипт поднимает неактивный цвет, ждёт его здоровья,
прогоняет миграции и только потом переводит nginx. Ручной `docker run`, правка
`*-upstream-active.conf`, остановка контейнера - всё это убирает страховку, и
посетитель получает 502.

Не хватает переменной - выясняй, откуда скрипт берёт значение. Придуманное наугад
уводит контейнеры на порты, куда nginx не смотрит.

## Обязательные переменные

Скрипт падает по одной за раз, поэтому собирай сразу все четыре:

| Переменная           | Откуда                                                                                |
| -------------------- | ------------------------------------------------------------------------------------- |
| `INFISICAL_HOST_URL` | домен своего Infisical (`server_name` в его nginx-конфиге)                            |
| `PRIMARY_DOMAIN`     | домен сайта                                                                           |
| `PORT_BASE`          | порт **blue**-контейнера, см. ниже                                                    |
| `GHCR_OWNER`         | `docker inspect <slug>-client-<color> --format "{{.Config.Image}}"` - владелец образа |

## PORT_BASE узнаётся у nginx, не выдумывается

База - порт blue; green стоит на `база + 100`.

```bash
docker exec <nginx> cat /etc/nginx/snippets/<slug>-upstream-blue.conf
# upstream <slug>_client { server 127.0.0.1:3040; }  →  PORT_BASE=3040
```

Ошибка, которая уронила whg 27.08.2026: взял порт живого green (3140) за базу.
Green переехал на 3240, nginx смотрел на 3040, сайт отдал 502 при «здоровых»
контейнерах. Инстансы делят один VPS, у каждого своя база с шагом 20.

## Порядок

```bash
curl -s https://<domain>/api/health          # что сейчас на проде
cd /opt/sites/<slug> && git fetch -q origin && git reset -q --hard origin/main
INFISICAL_HOST_URL=... PRIMARY_DOMAIN=... PORT_BASE=... GHCR_OWNER=...   nohup ./deploy/prod/deploy.sh > /tmp/<slug>-deploy.log 2>&1 &
```

Сборка идёт минутами, поэтому в фоне и с логом в файл.

## Проверка после - деплой без неё не закончен

1. `tail -3 <log>` - строка `✓ Deploy done. Active: <color>`
2. `curl -s https://<domain>/api/health` - **sha равен выложенному коммиту**
3. `curl -o /dev/null -w "%{http_code}" https://<domain>/` - 200, и страницы задачи тоже
4. `docker ps --format "{{.Names}} {{.Ports}}" | grep <slug>` - порты совпадают с активным снипетом nginx
5. Глазами на узком экране то, ради чего деплоил

## Грабли

- **Лок от упавшего запуска.** `another deploy is already running` при мёртвом
  процессе: `pgrep -af deploy.sh` ловит и сам себя, смотри на строку с путём
  скрипта, и только потом снимай `/run/lock/holygrail-<slug>.lock`.
- **Секреты без нового коммита** - `FORCE_REDEPLOY=1`, иначе тот же тег и ничего не произойдёт.
- **`PORT_BASE=3000 конфликтует`** - взял базу соседнего сайта.
- **Миграции** прогоняет сам скрипт на неактивном цвете, руками не нужно (`whg-payload-migration`).

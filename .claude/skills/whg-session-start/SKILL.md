# Skill: whg-session-start

> Это шаблон-конструктор, на котором уже живут пять сайтов. Всё, что здесь меняется,
> уезжает к ним синком. Работать по памяти и «по ситуации» тут нельзя: решения записаны,
> и их надо открыть, а не изобрести заново.

## Порядок старта

1. **План** — `grep -n "now=true" .claude/plan.kdl`. Он единственный источник очереди
   и приоритета. Ниже маркера очередь, выше - закрытое.
2. **Снимок прошлой сессии** — `.claude/session-context/current.md`: чем кончили,
   что не доделано, состояние среды.
3. **Правила** — `docs/whg/30-philosophy.md` (R1-R10) и skill `whg-rules`.
4. **Память проекта** — `~/.claude/projects/<путь>/memory/MEMORY.md`, раздел
   «Первым делом в новой сессии».
5. **Состояние выкладки** — что в удалённой ветке, что на рабочем сайте, зелёный ли
   последний прогон проверок. Незакрытая выкладка не даёт браться за синк.

## Куда идти за уточнением, прежде чем писать код

| Зона                                      | Читать до правки                                            |
| ----------------------------------------- | ----------------------------------------------------------- |
| Примитив, его свойства и поведение        | `docs/ux/primitives/`                                       |
| Раскладка страницы, панели, обрамление    | `docs/ux/layout.md`, `side-panels.md`, `content-framing.md` |
| Вид блока, что владелец правит сам        | `docs/ux/block-appearance.md`                               |
| Архитектурный выбор                       | `docs/whg/30-philosophy.md` + skill `whg-rules`             |
| Где живёт значение (код, база, Infisical) | `docs/whg/45-data-location.md`                              |
| Схема, миграции                           | skill `whg-payload-migration`                               |
| Синк сайтов                               | skill `whg-template-sync`, `docs/sync-journal.md`           |
| Выкладка                                  | `DEPLOY.md`, skill `whg-deploy`                             |
| Коммиты                                   | skill `whg-git-commit`                                      |

Нет ответа в документе - решение принимается и **записывается туда же**, а не остаётся
в переписке.

## Правила, которые нарушаются чаще всего

**Ничего не удалять из шаблона (R10).** Зеркало синка уносит удалённое из каждого
из пяти сайтов, и там встаёт сборка. Проверять ссылки в самих сайтах, а не в шаблоне.
Порядок: пометить `@deprecated` с заменой → перевести сайты → удалить.

**Не забирать вид, который владелец собрал руками.** Новая раскладка приходит свойством
рядом со старой. Пропавшая галка - это сломанная страница у живого сайта.

**План пишется до работы.** Пункт содержит механику, зачем, как, ожидание по каждой
проверке и признак готовности. Смоук - такой же пункт: ожидания записываются до прогона,
факт кладётся рядом после.

**Выкладка раньше синка.** Синк тянет из шаблона: пока правки не отправлены и не собраны,
по сайтам разъедется то, чего не видели ни проверки, ни рабочий сайт.

**Новый компонент размечает свои части** признаком `data-part` с ролевыми именами -
иначе владелец не дотянется до внутренностей через «Вид блока».

**Значения задаются так, чтобы их можно было перебить.** Базовое - в слое стилей,
поверх - поле в админке, главнее всего - CSS из «Вида блока». Инлайновый стиль в коде
запрещён: он бьёт правку владельца.

**Проверять глазами всё, а не то, что менял.** После правки примитива смотреть все его
состояния: ход, органы управления, обе темы, три ширины. Эталон поведения - рабочий
сайт, с ним и сверяться.

## Признаки, что скилл проигнорирован

- Правка кода раньше правки плана.
- «Похоже, работает» вместо сверки с ожиданием.
- Удаление файла из шаблона по проверке одного шаблона.
- Ответ по памяти о том, что написано в `docs/` или в skill.

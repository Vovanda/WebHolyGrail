# ADR-002: Целые микроединицы внутри, Money на границах

**Статус:** принято
**Дата решения:** 2026-10-23
**Приоритет:** критично для запуска
**Цена отката:** смена типа денег после реализации - переписать все денежные поля, расчёты, контракты и миграции данных.

## Контекст

1. Суммы складываются и делятся тысячи раз; дробные числа округляются по-разному в
   базе, на сервере и в браузере - сумма строк расходится с итогом.
2. JavaScript точен только до 2⁵³: целое число в микроединицах теряет точность уже на
   миллиардах.
3. Сумма без валюты в API читается неоднозначно.

## Решение

Мы будем хранить и считать сумму одним целым в микроединицах (×10⁶) внутри модуля. На
любой границе - фронт и бэк, сервисы между собой, вебхуки, события - сумма ходит только
объектом `Money { units, micros, currency }`: фронт так отправляет, бэк так возвращает,
сырое число не принимается и не отдаётся. Сумма в `Money` не отрицательная: знак несёт
вид документа. `Money` - открытый, в `contracts`.

## Альтернативы

- Десятичные дроби - программная эмуляция, разное округление на разных слоях.
- Числа с плавающей точкой - ошибка округления копится.
- Целые копейки - привязка к одной валюте и её точности.
- Одно целое в API - упирается в предел JavaScript, нечитаемо человеком.

## Риски

| Риск                                           | Приоритет | Цена, если сработает                  | Как нейтрализуем                                                 | Что остаётся                               |
| ---------------------------------------------- | --------- | ------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------ |
| Разработчик забывает шкалу                     | средний   | сумма в миллион раз больше или меньше | тип `Money` на границах, поля с единицей в имени (`priceMicros`) | работа с сырыми значениями в базе          |
| Переполнение при сборке `units × 10⁶ + micros` | низкий    | неверная сумма                        | предел `units` в проверке на входе                               | суммы больше ~9 млрд единиц не принимаются |

## Последствия

- Хорошее: суммы сходятся до единицы; атомарное обновление баланса - обычной записью.
- Плохое: на каждой границе перевод `Micros` ↔ `Money`.

## Соблюдение

Дробный тип в денежной логике и сумма не в `Money` на границе - блокер на ревью.

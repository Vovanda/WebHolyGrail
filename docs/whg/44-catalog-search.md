# Фильтр и поиск по каталогу

> Расширение магазина под флагом `shop.filters` ([`43-shop.md`](43-shop.md)).

> **Принят в работу 23.10.2026.** Решения ниже - умолчания, любое можно поменять.

Каталогу нужен фильтр по характеристикам и поиск, который понимает человека: опечатки,
другую раскладку, синонимы. Образец - DNS, разобран вживую 22.10.2026 на разделе
«Смартфоны». Первый потребитель - магазин мембран (материал, армирование, толщина,
ширина рулона).

## Что взято у DNS

| Приём DNS                                                          | Зачем                                              |
| ------------------------------------------------------------------ | -------------------------------------------------- |
| Панель слева: группы свойств, частые раскрыты, остальные свёрнуты  | на виду то, чем выбирают чаще                      |
| Счётчик у каждого значения: «Samsung (247)»                        | видно, сколько останется, до нажатия               |
| Диапазон «от и до» и готовые интервалы со счётчиками               | цену и толщину выбирают интервалом                 |
| Поиск по самим фильтрам                                            | при сорока характеристиках нужную не ищут глазами  |
| «Все фильтры»: окно с группами слева, «Применить» и «Сбросить всё» | много условий ставят разом и применяют одним шагом |
| Рецепты: готовый набор фильтров со своим адресом и текстом         | «С NFC», «256 ГБ» - отдельные страницы для поиска  |
| Подсказки поиска: продолжения запроса, «в разделе», бренды, товары | человек попадает в товар, не дойдя до выдачи       |
| `fqajy` → «айфон», «смартфн самсунг» → «смартфоны самсунг»         | раскладка и опечатки не оставляют пустую выдачу    |

## Позиции

Каталог - это витрина магазина: отдельного раздела `/catalog` нет, разделы живут по
адресу `/shop/<раздел>`, поиск стоит над плиткой, фильтр - слева.

Позиция каталога бывает обычной (остаток, количество в заказе любое в его пределах)
и штучной (один экземпляр: щенок на veo55). Штучную заказ бронирует - она пропадает
из выдачи с пометкой «забронирован» и возвращается при отмене. Позицией становится
сама запись продаваемой коллекции (собака veo55, видео, мембрана), без копии данных
([`43-shop.md`](43-shop.md), #167).

## Что уже работает

- Коллекция «Разделы каталога» (`catalog-sections`): название, адрес, описание и набор
  характеристик. У позиции - раздел, адрес, галерея, описание и значения характеристик;
  в админке значения заполняются полями своего раздела (`OfferSpecsField`), в базе
  лежат одним JSON по ключам.
- Раздел - `/shop/<раздел>`: поиск в разделе, фильтр по характеристикам и плитка тех же
  карточек, что на витрине (`OfferCard`). Пока сайт берёт раздел целиком и считает
  выдачу у себя; переход на индекс каталога и выдачу страницами - «Выдача страницами»
  ниже. Без JS страница работает целиком.
- Позиция - `/shop/item/<адрес>`: крупный кадр и остальные плиткой, цена, корзина,
  характеристики раздела таблицей (`cardSpecs`), описание. Адрес позиции не зависит от
  раздела: перенос между разделами не ломает ссылки.
- Пока не сделано: панель фильтра в боковом слоте раскладки (сейчас - колонка слева
  на странице, на телефоне свёрнута), окно «Все фильтры», рецепты, подсказки поиска,
  список нулевых запросов, отзывы и «похожие» на странице позиции.

## Характеристики

Набор характеристик задаётся у раздела каталога в админке, без разработчика. У каждой:

| Свойство          | Значения                                                |
| ----------------- | ------------------------------------------------------- |
| название, единица | «Толщина», «мм»                                         |
| вид значения      | перечень, число, да/нет, текст                          |
| группа            | «Основные», «Размеры» - для панели и окна «Все фильтры» |
| вид в фильтре     | галочки, диапазон, готовые интервалы, не показывать     |
| в карточке        | показывать ли и в каком порядке                         |

Товар хранит значения по характеристикам своего раздела. Новая характеристика не требует
миграции: описание характеристик - данные (та же мысль, что в [`47-forms-records.md`](47-forms-records.md);
общее у них выносится, когда оба заработают, R9).

Второй источник характеристик - собственные поля продаваемой коллекции: у собаки порода
и окрас уже лежат полями, и владелец отмечает их характеристиками, не дублируя в наборе
раздела.

Запросы Payload внутрь JSON-поля характеристик в SQLite не работают: значение с
кириллицей адаптер отклоняет, диапазон по числу падает (проверено 24.10.2026, #150).
Поэтому фильтр и счётчики считает индекс каталога (ниже) чистыми функциями
`contracts/src/catalog.ts`. Один модуль поиска работает и в выдаче, и в корзине.

```
│ [от] — [до]  │ │ │    │ │    │ │    │ │    │               │

```

Поиск и быстрые фильтры стоят над плиткой и шириной с неё: они сужают ту же выдачу,
что лежит под ними. Расширенный фильтр живёт отдельно: кнопка «Все фильтры» в строке
быстрых фильтров открывает боковую панель `SidePanel` слева, как у плейлиста, и панель
сдвигает страницу. Плитка занимает всю ширину и стоит по центру.

**Магазин целиком** - `/shop`. Сверху те же поиск, быстрые фильтры и «Все фильтры»,
только условия общие для всех разделов: наличие, скидка, цена. Ниже каждый раздел
своим блоком: заголовок со счётом позиций, ряд из четырёх карточек и ссылка «Все N
позиций» в раздел. Задан запрос или фильтр - разделы уступают место общей выдаче по
всему магазину.

**Быстрые фильтры** - строка переключателей под поиском, как подборки сверху раздела
у DNS и ВсеИнструменты. В строке два постоянных переключателя, «В наличии» и «Со
скидкой», и значения характеристик, у которых в разделе отмечено «в быстрых
фильтрах». Переключатель - ссылка на тот же адрес фильтра, что и галочка в панели:
нажатый в строке отмечен и в панели, и наоборот.

## Выдача страницами

Выдача считается в CMS, а сайт получает одну страницу. Так страница раздела весит
одинаково и при двадцати позициях, и при десяти тысячах.

**Индекс каталога** - порт с тремя действиями: положить, убрать, спросить (R8). Первое
исполнение держит позиции в памяти процесса CMS уже в виде для фильтра: значения
характеристик раздела и общих (наличие, скидка, цена) по ключам. Фильтр, счётчики,
поиск и сортировку считают чистые функции `contracts/src/catalog.ts`, те же, что
проверены тестами без базы.

**Свежесть.** Экземпляров CMS бывает больше одного: при выкладке синий и зелёный
работают на одной базе. Поэтому индекс не полагается на хуки правки, которые сработают
только в принявшем запись экземпляре, а перед ответом сверяет версию данных одним
запросом - число позиций и время последней правки позиций и разделов. Версия
разошлась - индекс пересобирается в фоне, а запросы до конца пересборки получают
прежний снимок: чтение десяти тысяч позиций через Payload занимает секунды, и
покупатель их не ждёт. Первая сборка идёт при старте CMS, вместе с ней строится
обратный индекс слов для поиска. Одинаковые запросы к одному снимку не считаются
заново.

**Замер** на 10 000 позиций (24.10.2026, dev-сервер, ручка без расчётов отвечает
за 32 мс): раздел и фильтр с сортировкой - 30-36 мс, поиск с опечаткой - 28-40 мс,
первый запрос после старта - 90 мс при фоновой сборке 4,6 с.

**Ручка** `/api/shop/catalog`: на входе раздел, запрос `q`, условия фильтра, сортировка
`sort` и страница `page`; на выходе позиции страницы (до 30), фасеты, число найденного
и число страниц. Без раздела и без условий ручка отдаёт превью разделов для `/shop`:
по пять позиций и число в каждом - одним ответом вместо запроса на раздел.

**Сортировка**: по умолчанию (как в админке), цена по возрастанию и по убыванию,
размер скидки, новизна.

**На сайте** первая страница рисуется на сервере (R14), дальше фильтр, сортировка,
поиск и «Показать ещё» запрашивают ту же ручку через `/internal` (R15) без
перезагрузки, а адрес в строке браузера меняется вместе с выдачей (R13). У каждой
страницы выдачи свой адрес `?page=N`: «Показать ещё» дописывает следующую страницу
под текущей, а ссылки на страницы внизу ведут поисковик по всему разделу.

**Когда менять исполнение.** Позиции в памяти и пересборка за один проход годятся до
десятков тысяч позиций. Дальше за тем же портом встаёт Meilisearch: ручка, контракт
и сайт не меняются.

## Фильтр

**Состояние - в адресе** (R13): `?material=pvc&thickness=1.2..2.0`. Ссылкой на подборку
делятся, поиск её индексирует, а со списком работают и без JS (R14): каждое значение
фильтра - ссылка.

**Счётчик значения** считается при остальных выбранных условиях, без условия своей
группы: иначе у выбранной группы остаётся одно значение. Значение, при котором товаров
не останется, видно приглушённым.

**Где стоит.** Панель в слоте `left` раскладки сайта с `mobile: "push"`: на узком экране
она выезжает и сдвигает страницу, фильтр - часть той же работы
([`panels.md`](../ux/layout/panels.md)). Маска адресов - страницы каталога.

**Пачкой.** На телефоне галочки копятся, и снизу всплывает «Показать N товаров». На
широком экране то же делает окно «Все фильтры». Одна галочка в панели на широком
экране применяется сразу.

**Рецепт** - запись в админке: раздел, набор условий, название, адрес и текст. Живёт
по адресу `/shop/<раздел>/r/<рецепт>` со своим заголовком и описанием для поиска.
Сверху раздела рецепты идут строкой ссылок, как у DNS.

## Поиск

**За своим слоем доступа** (R8): у индекса три действия - положить, убрать, спросить.
Первое исполнение - в процессе сайта: каталоги наших сайтов - десятки и сотни позиций
(R7). Когда позиций станут десятки тысяч, рядом ставится отдельный сервис поиска
(Meilisearch), а сценарии и контракт не меняются (R4).

**Что делает с запросом**, по порядку:

1. приводит к одному виду: нижний регистр, ё → е, лишние пробелы;
2. если запрос набран не в той раскладке и в своей даёт слова из словаря - берёт свою;
3. транслит и синонимы из словаря в админке: «iphone» = «айфон» = «Apple iPhone»;
4. каждое слово ищется по началу и с допуском опечатки, от длины слова: до 4 букв -
   без допуска, до 8 - одна правка, длиннее - две. Это умолчания Meilisearch
   (`minWordSizeForTypos`: 5 и 9), чтобы при переезде на него выдача не изменилась.

**Где ищет и с каким весом:** название, артикул, раздел, значения характеристик,
краткое описание - в этом порядке.

**Подсказки** по мере набора, с третьей буквы:

- продолжения запроса из прошлых удачных поисков;
- «в разделе»: запрос внутри подходящего раздела;
- товары с фото; цена - по тем же правилам видимости, что в каталоге.

**Выдача** `/search?q=` - тот же список, что в разделе, с той же панелью фильтра.

**Нулевые запросы** складываются в список в админке: по нему владелец дописывает
синонимы, и следующий человек уже найдёт.

## Контракт

| Что                               | Где                               |
| --------------------------------- | --------------------------------- |
| характеристики, состояние фильтра | `contracts/src/catalog.ts`        |
| фасеты и счётчики                 | чистые функции, проверка без базы |
| индекс и запрос                   | слой поиска за интерфейсом (R8)   |
| подсказки из браузера             | `/internal/search/suggest` (R15)  |

## Откуда берётся

Магазин мембран: `roof-membrane/src/client/src/lib/domain/shop/catalog-filter.ts`
(фасеты по свойствам, счётчик без своей группы, состояние в адресе) и `catalog.ts`
(поиск без учёта регистра, с ё). Там же причина не искать в SQLite через `LIKE`:
он не различает регистр только у латиницы, «клей» не находил «Клей».

## Умолчания

1. Каталоги ближайшего года - сотни позиций (мембраны - 18). Поиск в процессе сайта,
   Meilisearch - когда позиций станет больше десяти тысяч.
2. Рецепты - вторым шагом, после фильтра и поиска: у мембран пока нечего в них класть.
3. Только каталог. Поиск по статьям и страницам - отдельный пункт, тот же слой индекса.
